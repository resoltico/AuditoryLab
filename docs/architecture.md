# Architecture

The workspace separates validated stereo generation, output adapters and frontend presentation. `auditory-app` is the shared application boundary for frontends.

| Crate | Responsibility |
|---|---|
| `auditory-core` | The preset format, the built-in catalog, validation and sample generation. |
| `auditory-wav` | Stereo float RIFF/RF64 encoding to a caller-owned writer. |
| `auditory-device` | Default-output discovery, sample conversion, channel placement and playback supervision. |
| `auditory-app` | Bounded input, catalog workflows, typed notices and failures, preparation, cancellation and staged file publication. |
| `auditory-cli` | The `auditorylab` command: arguments, stdin, presenting results, exit statuses and interrupts. |
| `auditory-gui` | Native Slint controls, selection/path forms, worker lifetime and presentation of app-owned values. |

The sinks depend on the core; the application depends on the core and sinks. The frontend depends only on `auditory-app` for domain behavior. It supplies input and renders typed values and failures. Opaque loaded and prepared values expose immutable descriptions and resolved facts without sessions, renderers or native handles. Structural decoding remains distinct from rate-dependent session validation.

## Core

`Preset` holds a `Stimulus` and optional `About` text. A stimulus is a list of components, each a tone or click carrier with ear routing, a peak level and an optional sinusoidal or rectangular modulation; see the [format](presets.md).

`Preset::from_bytes` checks byte length and UTF-8, then delegates to `Preset::parse`. The latter accepts `&str` and checks length, the schema version and strict structure. `Stimulus::session(rate)` checks timing, the component count, each component in order, then each ear's summed peak, and returns an opaque `Session`. Values can be invalid until this point.

A `Renderer` takes a session's frames from the first, filling `[[f64; 2]]` buffers and returning an immutable `RenderedSpan`: the authoritative starting source frame and active prefix length, with an exclusive end. Empty renders do not advance the cursor; the remaining caller buffer is zeroed and is outside the active source span. Tone and sinusoidal phases are binary64 cycle accumulators that persist across buffers. Clicks and rectangular modulation share one pulse-train generator whose phase comes from the absolute frame index.

Carriers lie within ±1 and modulation and fade gains within 0 to 1, and each ear's peaks are summed in the order its samples are, so round-to-nearest arithmetic keeps every rendered sample within the validated bound without clipping. Rendering allocates nothing, takes no locks and performs no I/O, so it can run on an audio thread.

The core is `no_std` with `alloc` and uses portable `libm`. The workspace enables `force-soft-floats`, which overrides architecture/intrinsic features even when GUI transitive dependencies enable them through Cargo feature unification. This preserves the same arithmetic across frontends and supported targets; independent formulas and pinned digests check it wherever they run. The catalog's TOML files are compiled in with `include_str!`.

## Sinks

WAV encoding renders 4,096-frame blocks, rounds samples to 32-bit float and writes the header and samples to a caller-owned writer. It performs no destination I/O. The session length decides between RIFF and RF64. The application shares one same-directory staged no-clobber publisher between WAV export and recipe saving, preserving ordinary output permissions. [Usage](usage.md#new-file-publication) states the file-ownership contract.

Device discovery saves one backend-reported default stream configuration; the session must match its rate, which does not certify the physical hardware rate. The audio callback converts samples, places left and right on the first two channels and silences the rest, using preallocated scratch. Callbacks and the supervising thread publish one fixed terminal code using a compare-and-exchange from Running. The first publication wins. One separately elected asynchronous reporter stores a backend diagnostic before publishing Backend; synchronous setup failures keep their error on the worker and publish StreamSetupFailed directly. Sample callbacks never initialize or access diagnostic payloads and silence a buffer when they observe a terminal code; sound already queued to the backend cannot be recalled. Completion requires a callback at or after the latest backend estimate of when the last frame plays. The application supplies typed low-volume and separate-ear headphone notices before playback, and a typed nonzero-underrun notice on completion. Native error dispatch can allocate or lock; the bounded publication guarantee is for application-owned sample processing. Stream destruction is not assumed to join every native callback.

## Generated signal observation

Optional playback observation consumes the same mixed, faded stereo f64 samples already generated by the core, before sample conversion/channel placement. It does not resynthesize a preview, tap a microphone or describe the OS mixer/sound pressure. Rendering may precede audible playback, and cancellation can silence a buffer after its source samples were generated.

The renderer's active source span drives observation and progress. Pure core history/reduction retains separate-ear extrema in integer-frame buckets anchored at source frame zero, plus capped recent detail. Coarse views combine whole buckets and expose their actual covered span; exact detail stays within retained raw data. Missing intervals and partially observed buckets remain gaps, not zeros or connected paths. The broad view is a Peak range, not an analytical modulation envelope, RMS or FFT.

The device publishes at most one fixed, heap-free packet per existing audio chunk into a preallocated safe SPSC transport. Full/disconnected transport drops visual data immediately; sample processing does not wait, retry, allocate, log or invoke GUI code. A separate latest-generated cursor advances from authoritative spans even when packets drop. The app's bounded poll/history work compares coverage to that cursor, discards stale backlog and measures time since genuinely new coverage; packet receipt alone does not make data live.

Capacity is checked from the actual prepared rate before audio starts. The product contract is a 250 ms transport target rounded to packets, recent peak history up to two seconds, detail up to 100 ms, at most 2,048 coarse buckets and 1,024 output bins per ear/view, within an 8 MiB monitoring capacity cap. The app computes its own transport/history/snapshot capacities and composes them with an explicit caller-owned presentation reservation. The GUI owns bounded string construction, actual String-capacity checks and its pinned Slint conversion/live-copy reserve; the app contains no renderer path or label counts. Admission first checks the predicted app allocation plus reserve, then verifies actual typed capacities after construction. Independent consumers must supply and verify their own reserve; arbitrarily retained additional snapshots and native graphics/process RSS are outside that cap. Low-rate windows expose their actual sample extent rather than invented interpolation. Audio rate/validity limits are never reduced to fit a plot.

The worker keeps native playback while the UI receives an opaque app observation handle before the existing start permit. Immutable snapshots retain operation/source identity, actual rate, frame coverage, gaps and freshness. The GUI maps supplied values to geometry and one shared fixed amplitude reference; it does not select extrema or invent progress. Signal through/Last observed frame describes chart coverage, not an audible or draggable playhead. Freeze display leaves sound running; hidden/frozen views avoid rendering/draining old data as current on resume. Actual terminal results remain authoritative and separate from the last real snapshot.

## Command line

The terminal uses lexopt for native lexical handling and one command metadata authority for accepted options, required output and help. It parses explicit catalog ID/--file/--stdin grammar and supplies its locked stdin to the application reader. The application bounds input and assigns a typed origin, prepares facts from the actual session once, and binds playback to one discovered output snapshot. The command line presents its results: technical reports quote untrusted text, `describe` wraps it, and the human writer escapes control characters. A separate narrow writer preserves exact catalog recipe bytes. Application-created immutable failures carry typed input/schema/span, core validation, backend-independent device and filesystem-phase facts, with original thread-safe technical causes; the terminal maps these to exit statuses. Interrupt handling starts only after input has been read.

## Desktop controller

The GUI uses Slint's Winit backend, accessibility integration and stable FemtoVG/WGPU renderer alongside software. The actual dependency profile is checked against Cargo's selected graph. GUI drawing uses one compatible graphics adapter; sound synthesis remains on the CPU. Early renderer/no-adapter construction can fall back to software; later surface/device loss does not promise a universal renderer switch. A per-process `SLINT_BACKEND=winit-software` is the recovery route. Reactive presentation avoids replacing equal catalog models or continuously repainting idle content. A narrow pinned Slint `unstable-winit-030` bridge borrows focus state and observes occlusion events without consuming them; the GUI retains no native window handle or graphics API. Live monitoring runs only while focused, unminimized and not reported occluded. This conservative focus policy can suspend an unfocused window even when it remains visible; it does not claim complete compositor visibility knowledge.

Wayland client decorations keep their title text and controls through Winit's supported crossfont route. A manifest-only SCTK patch aligns crossfont with Slint's Fontconfig producer. Both supported Linux Cargo targets override `links=freetype` to `dylib=freetype`, which skips freetype-sys build.rs and its bundled native fallback entirely. Root GUI source builds require security-updated distribution FreeType/Fontconfig; the final GUI must import both system libraries. The CLI does not link these font libraries.

Handwritten controller state is separate from Slint bindings. One owning worker performs blocking application operations; native playback capabilities stay on it. A prepared transferable view reaches UI-thread state before a matching start permit. This is state delivery, not proof of painted pixels or a completed screen-reader announcement. Reliable preparation/result channels remain separate from lossy signal observation. Stale operation IDs cannot relabel a running or completed result.

A native chosen `PathBuf` is distinct from its display string and an explicitly entered manual draft. Editing changes path authority; cancelling edits restores the choice. No-selection from a native chooser preserves state without inventing a cancellation reason. Close/Stop requests cancellation and waits for the actual result and worker termination before joining and closing; pending native dialogs retain their parent. The narrow [backend patch](../vendor/slint-winit/AUDITORYLAB.md) routes ordinary macOS menu/Dock Quit through this same close path. Force termination and OS logout negotiation are separate limits.

## Build identity and native artifacts

The app owns immutable build identity. Common source/kind metadata comes from app/build.rs and Cargo TARGET; each frontend selects its checked Product at the call site. Both absent qualification inputs mean local/unqualified with no source SHA. Malformed or partial inputs fail, and Cargo tracks identity changes across cached builds. `--build-info` is a narrow artifact-verification response, not a general command-output format.

[release.py](../scripts/release.py) defines the checked products and six native targets, including the common macOS 15.0 deployment minimum for both products and architectures. [qualify.py](../scripts/qualify.py) owns code checks, tests, isolated product builds and native packaging; the reusable workflow runs that same path. Native import policies remain specific to each product. Windows receipts bind product/bin/object identity and actual reviewed native inputs to executable/map bytes. GUI system-import libraries have a separate source-bound review; GPU drivers/loaders may load dynamically and cannot be certified from import tables alone.

[package.py](../scripts/package.py) checks exact product members, extracted executable identity, platform/import/floor rules and independent silent export/no-overwrite behavior. Native window/actual-renderer checks remain separate from no-display smoke and from accessibility, picker and acoustic evidence. [notices.py](../scripts/notices.py) retains runtime dependencies, separately labeled host code-generation material, generated widgets/assets and complete Rust/native bundles. Reviewed vendored source cannot disappear merely because Cargo reports source=None. [Releasing](releasing.md) describes the source and publication boundary.

## Changing the model

A new component or modulation kind needs its core variant, validation, generator and display text, the [format](presets.md) documentation, and tests that check it against independent formulas, its rejection boundaries, allocation-free rendering and buffer-partition independence, plus a pinned digest. Existing digests change only when their samples deliberately change. Sinks consume validated sessions, and both frontends present application-owned values; neither frontend needs waveform-specific logic.

## Frontend enforcement and worker use

The thin `auditory-app/tests/frontend_boundary.rs` driver enforces a finite role for every workspace member. Private role, source and GUI-compiler modules check library/frontend/build/test target kinds, allowed dependency directions across every dependency kind, target conditions, aliases and canonical production roots. Unclassified members and internal binaries reject; frontend syntax checks also inspect cfg-disabled code. CLI and GUI have separate presentation allowlists; both use only the app for domain workflows. GUI alone has a reviewed contained Slint compiler/build script and generated-only inclusion module. Its checked lint copy differs only at the unsafe level needed by generated code; handwritten GUI unsafe syntax is rejected, and other workspace crates keep forbid.

Workspace, package, source and admitted resource roots are anchored before traversing descendants; moving a whole root cannot reset its authority. Rust/UI/resource paths and actual compiler-reported inputs must stay in those permitted canonical roots. Unsupported compiler `SLINT_*` and MCU overrides reject; qualified builds check that precondition on every invocation, including Cargo cache hits. Explicit resource embedding prevents build-host absolute asset references. Inclusion imports/aliases and unsupported syntax forms reject rather than silently escaping traversal. AST/compiler parsers remain dev-only. These controls do not detect arbitrary copied algorithms or prove semantic equivalence; review domain policy, signal reduction and presentation dependencies deliberately.

Cancellation is an operation-local cloneable handle. Blocking preparation and playback execution involving native handles stay on one worker; native prepared playback need not be Send. Owned descriptions, reports and application errors are Send + Sync + 'static, so a worker can send results to a UI thread without backend handles. Public facade examples and integration tests demonstrate this consumer contract.

Declared descriptions are immutable device-free snapshots of typed origin, About, declared duration/fade, components, canonical ear assignments and app-owned notices. Facts embeds the same declaration and derives resolved durations from validated frames/rate. Inspection renderers take Facts alone; export/playback preparation renderers take app-created bound views. Export binds the native destination at preparation and executes with cancellation only. Owned completion reports keep private source/destination context and one sink result; rendering cannot substitute a separate identity or path.

File loading admits only regular opened handles, including regular-file symlink targets. Unix opens nonblocking before validating the handle, so replacing a checked path with a FIFO cannot make that open wait for a writer. Explicit `load_reader`/CLI `--stdin` retain stream semantics and byte limits. Regular-file admission does not establish deadlines for stalled network filesystems or arbitrary OS calls, and captured bytes are not an atomic filesystem snapshot.

Presentation notifications retain their own state and cannot replace an operation’s genuine preparation, permission or terminal result.

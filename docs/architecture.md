# Architecture

Auditory Lab has a pure synthesis core, one shared application library and two frontends. Cargo's direct dependencies express the direction: CLI and GUI depend on `auditorylab`, which depends on `auditorylab-core`. The library re-exports the model types callers need. Frontends render shared views and own their windows, terminals and threads; domain and workflow decisions belong in the library and core.

| Package | Responsibility |
|---|---|
| [`auditorylab-core`](../crates/core) | Recipe schema and model, semantic parameter descriptors, validation, compilation into targets, seekable and live synthesis, recipe writing, timing models and waveform extrema. `no_std` with `alloc`. |
| [`auditorylab`](../crates/lib) | Recipe snapshots, editing sessions, control ranges, WAV export, staged file publication, portable playback sessions and monitoring, the interactive `Workspace`, shared presentation and, with the `device-playback` feature, default-device playback. |
| [`auditorylab-cli`](../crates/cli) | clap grammar, terminal layout, exit codes and interrupts; binary `auditorylab`. |
| [`auditorylab-gui`](../crates/gui) | Slint windows, the adapter that binds them to a `Workspace`, native dialogs, preferences and macOS application integration. |
| [`xtask`](../xtask) | Archives, notices, smoke checks and release notes. |

## Recipe to signal

`Recipe` contains an `AuthoredStimulus`, portable identity/history, description and bounded bibliography/evidence/flat lineage. Authored raw primitives and signed-offset pairs lower into the existing `Stimulus`/`Target` generators with typed owner/lane IDs; both authored and expanded budgets remain 16. `About`/`Research` are derived presentation views. A component has ear routing, peak level, a tone or click carrier (`CarrierKind`) and optional sinusoidal or rectangular modulation (`ModulationKind`). Every editable quantity has a `ParameterId` whose descriptor gives its label, display unit and help; reads and writes of component values go through it. A private serde representation keeps the strict schema independent of the public model.

Parsing checks byte length, UTF-8, schema version and TOML structure. Validation is compilation. `TargetCheck::new(rate, components)` compiles each identified component once at one rate and keeps every component's own result, then checks identities, count and each ear's summed peak. Its `Target` is the validated mix: compiled voices plus each component's requested and realized facts. Two targets are equal only when their definitions are, including requested values that round to the same audio; `Target::same_audio` compares only what is generated. `Target::signal(duration, fade)` adds the finite envelope to give an immutable `Signal`. Errors name the parameters they concern, in display units.

Tones and sinusoidal modulation have a 64-bit integer phase step, rounded upward from the exact binary64 frequency ratio. Frame n uses wrapping multiplication by n. Tones convert the phase's signed top 53 bits to cycles before evaluating portable `libm` sine. Pulse width is rounded to whole frames; facts keep the requested width beside the realized frame count and rate. Exact rational period counts place each onset on the first frame at or after it; comparing counts at n and n−W gives a constant open width. The exact closed-frame rule keeps successive pulses separate. Voices are summed in recipe order, then the raised-cosine fade applies. The [recipe guide](recipes.md#waveforms) defines the formulas.

`Signal::frame(n)` evaluates any frame directly. `render(start, out)` fills an arbitrary block, returns its active length and zeros the tail. It allocates nothing, locks nothing and performs no I/O. Each output owns its cursor. Integer phase, binary64 arithmetic and portable `libm` preserve sample bits across platforms and build profiles; pinned digests test that contract.

The pure `nominal` module classifies authored primitives without compiling targets or rendering samples. Immutable recipe snapshots cache their nominal analysis, and editor sessions cache committed analysis by draft revision independently of staged text and sample rate. Confirmed save candidates supply the separate saved classification. Shared nominal facets correlate band and method within one descriptor; both CLI and Slint use them. Library rows no longer compile every sound at the export rate.

Catalog source files are embedded by the core build script in natural ID order. `waveform::trace` renders every frame of a clipped window into fixed stack scratch and reduces equal partitions to per-ear minima/maxima. Single-frame pulses reach their bins' extrema.

## Live synthesis

`Engine` generates one `Target` at a time in 32 fixed slots, so all 16 components can crossfade with replacements. It allocates nothing while setting targets, rendering or stopping. Its destination (the target it is moving to) is separate from a pending target waiting behind a transition. A revision whose target has the same audio as the destination is applied at once: the destination, its revision and the facts of slots that are not fading out change, and no ramp starts. Other revisions start a 30 ms transition or wait as the newest pending target.

Tone and sinusoidal-modulation oscillators advance integer phase accumulators. Constant settings match the seekable signal after the start ramp. A transition interpolates per-ear levels, phase steps and depth. Matching component identities and generator kinds retain phase; pulse or kind changes crossfade generators. Each transition connects validated endpoints with shared progress, bounding the per-ear sum. Stop queues silence after the current transition; its fade takes 30 ms. The engine ends at `Signal::MAX_FRAMES`.

Within each live frame, voices with exactly equal modulation phase reuse the portable sine result. This bounded one-entry value is discarded at the next frame. Each voice still evaluates its own depth and normalized gain and advances its own phase; carrier evaluation and mixing order stay unchanged.

## Recipes, editing and files

A loaded `RecipeSnapshot` is immutable: complete authored content, `Origin` and a process-local `SnapshotId`, distinct from the document UUID and its declared dates. Loading the same path again gives a new identity. `RecipeSnapshot::at(rate)` returns a `Sound` with an `Arc<Signal>`. Files are opened nonblocking on Unix, and admission checks the opened handle before bounded reading. Errors carry a category, contextual message, original cause and an optional leftover path; frontends branch on the category.

An `EditorSession` owns one document: a `DocumentId` that is never reused, the committed `Draft` with stable component identities, staged text per `EditingField`, the saved-content baseline and cached evaluations. Every editing command carries a `FieldHandle` (document and field) or a document and component identity, so a late command for another document is refused. Staging changes only diagnostics and readiness. Committing parses the whole candidate: an unparseable field or any nonfinite value, typed or inherited, commits nothing and keeps all staged text; a parsed finite candidate commits even when acoustically invalid. Structural changes discard only the staged fields they make inapplicable. Evaluations are cached by draft revision, input revision and rate; save readiness is cached by revision. A document is dirty while anything is staged or its content differs from the saved baseline.

Readiness differs by operation. Save needs a complete serializable candidate. Export needs a valid finite signal at the selected export rate. Requesting device playback needs only a complete finite candidate and admission: the device's actual rate decides validity during preparation, independently of the export rate.

WAV encoding renders blocks and rounds to stereo binary32 samples. Header size arithmetic chooses RIFF or RF64. Publication checks cancellation, rejects an existing destination before writing anything when replacement is not allowed, stages output in the destination directory, syncs it, checks cancellation once more and publishes the completed file. Confirmed replacement uses atomic persistence. No-overwrite persistence never replaces an existing destination, but its link-and-cleanup operation is not guaranteed atomic on every platform. File sync does not guarantee directory-entry persistence after power loss. Successful persistence is final: a later cancellation cannot unpublish it. Failure cleanup removes only its own stage and names it if removal fails.

## Sessions and playback

A `Session` owns one playback lifecycle and cannot be cloned; preparation consumes it. `PlaybackControl` handles address that session only. One atomic outcome word arbitrates the lifecycle: Running and StopRequested are active, every other outcome is terminal and the first terminal publication wins. Stop accepted before completion drains as Stopped; a failure wins from either active state; dropping the owner unfinished records Abandoned. Generation ending is a separate fact that closes live-update admission.

`LiveGenerator` generates a `Target` without a device; `LiveControl::update` accepts a target at the session's rate under a new revision, keeps the revision for an identical definition and refuses updates after Stop or source end. Accepted is not generated: active and settled revisions follow actual generation. A finite source fades with gain `1 − (t+1)/R`, with R capped at its remaining frames.

The session, sources, transport arithmetic, supervision and monitoring are portable. The `device-playback` feature adds CPAL discovery, stream setup and timestamps. `device::prepare_playback` and `device::prepare_live` validate their source at the default device's actual rate before the stream starts, or report Stopped when Stop arrived first. The transport keeps three positions apart: source frames generated, backend frames submitted including drain silence, and the estimated output position from backend timestamps. Supervision waits for the terminal outcome with a 30-second stall watchdog and a two-second bound after Stop, after which it forces silence. Output conversion uses channels 0/1 for left/right and silences additional channels.

## Workspace

`Workspace` is the interactive state shared by desktop frontends: the library and its search and selection, the current view, the selected export rate, one editor, exactly one audio task slot and one file task slot, at most one prompt and at most one queued action. Frontends send typed commands, perform the `Effect`s it asks for — ask about unsaved changes, choose a path, resolve a close request, show a view — and answer with typed `Response`s carrying the prompt identity; an answer to a prompt that is no longer open changes nothing.

Play and Live need idle audio and no export; Save and Import may run beside audio; Export needs idle audio and file slots. Stop acts only on audio and cancelling an export only on the export. Without device playback, audio is refused before a slot is taken. A task keeps its slot until its thread has finished and been joined, even after its result arrived. Queued actions wait for exactly the tasks they depend on and run only after the join: replacing audio waits for the previous audio session, document replacement waits for file work, closing waits for both. Expected Stop and cancellation count as cleanup; a real failure blocks only the actions that depend on it. Save before close or replacement continues only if that save published, its worker joined, the document is the same and nothing newer is unsaved. Repeated close requests coalesce, and every close entry point uses the same decision.

A live preparation attaches monitoring to its own session. If the session still belongs to the open document and admission is open, the current committed draft is compiled at the device's actual rate and submitted when valid; staged text is never sent. Later commits are submitted the same way.

Views are built from the same rules the commands use: editor rows with semantic parameters and diagnostics, library details, action availability and reasons, transport text and the output view. Work happens only when its inputs change. A static preview is generated once per source identity, committed revision, rate and span; a scale change reuses its samples; an invalid source caches its diagnosis. A monitored capture is rebuilt for a new publication, span or scale. A held capture is an immutable value that later navigation, edits, settings or sessions cannot relabel. The timing model follows a bound live session's accepted revision, otherwise the shown source at its rate. `Workspace::shutdown` stops audio, cancels an export, waits for saves and imports, joins both workers and reports actual failures.

## Frontends and packaging

The CLI uses the synchronous library capabilities directly, without a `Workspace`: clap for source exclusivity and command grammar, textwrap for prose and a byte-preserving catalog recipe writer. The first interrupt requests Stop or export cancellation; a second exits. One mapping from library error category selects the exit code.

The GUI's `SlintAdapter` is its only binding to the workspace; startup and the offscreen tests install it the same way. Each generated callback becomes one workspace command, followed by its effects and a projection. Component rows and their nested parameter rows are persistent models reconciled by component identity and parameter key, so surviving fields keep their widgets, focus and caret; only a replaced document resets them. Parameter rows carry a semantic `ParameterKey` mapped exhaustively to `ParameterId`. Rows carry an integer binding that names one document or one component of one document and is never reused; a field keeps the binding its edit started with, and replacing a document suppresses automatic blur commits. Document views are projected when the workspace revision or audio phase changes; telemetry is projected on each tick without rebuilding waveform paths unless the capture changed. A tick polls every 50 ms while work runs and every 200 ms when idle.

Dialogs and file panels are asynchronous and parented to the main window. On macOS, Quit and About arrive through the Slint backend's application handler: termination is answered “later” and the reply follows the workspace's close decision, after the tasks it depends on have joined. The application menu's About item routes through a reserved menu identifier. A native file panel shows a Stop button whose target holds the control of the session playing when the panel opened; Stop never closes the panel or affects its file operation. Windows and Linux show a separate audio-controls window while a native panel is open.

`cargo xtask dist` builds one supported target, generates product-specific notices and archives, then extracts and inspects the delivered binaries. macOS executables must have exactly one expected architecture; app marketing version/build counter, signature, permissions and executable identity are checked. `collect-assets` derives the complete archive set from the same target/product mapping and rejects missing, duplicate, stale or unexpected files before checksums/attestation. The reusable [CI workflow](../.github/workflows/ci.yml) supplies release builds; the [release guide](releasing.md) describes source identity, archive formats, icon/legal resources and publication.

## Generated observations

Core component facts distinguish requested rates and actual integer-phase rates. Rational pulse repetition and rounded width frames retain their rendering semantics. `Engine::observation` is side-effect-free fixed storage for the last generated frame (or None before generation), with up to 32 outgoing/incoming/continuing slots and active/settled target revisions. Core code has no device clocks, locks, frontend strings or monitoring I/O. Observation does not change sample formulas or determinism.

The library binds a process-local session ID, source snapshot and device configuration before playback. Optional monitoring has quantities-only or waveform detail. A callback attempts one nonblocking mutex acquisition per device buffer. It appends actual mixed/faded/clamped stereo f64 scratch samples before output conversion and publishes coherent generated-frame state. It neither copies old history nor formats/reduces/allocates under the callback. A skipped write creates a source-span discontinuity; the next write resets contiguous history. Poisoning disables observation with an off-callback diagnostic, independently of audio terminal authority.

Waveform storage is at most ceil(sample-rate/10) stereo frames: 76,800 frames (1,228,800 sample bytes) at 768 kHz. All transport and consumer storage is allocated during preparation, including initialization of lazily allocated mutex storage. Readers use try_lock to copy only the requested bounded window into preallocated storage, then release it before calculating extrema, peak/RMS, descriptions or paths. Quantities-only mode allocates no sample history. Monitoring misses and backend underruns are distinct counters.

The core `Structure` interprets independent click/gate/AM processes, inactive modulation, steady carriers and narrow equal-gain same-route monaural pairs. It recognizes interaural difference only for exactly one active unmodulated left-only tone and one right-only tone. It reports individual generator quantities/roles for other mixtures and crossfades. Status identifies the last generated frame; window spans identify the displayed samples. Neither is microphone input, SPL, a perceived-beat measurement or a latency-aligned acoustic playhead. The backend estimate is the authority for estimated output elapsed time, and terminal/drain logic decides completion even if monitoring misses its final publication.

## Build identity

`workspace.package.version`, the positive `workspace.metadata.auditorylab.build-number` and an optional validated source revision are separate facts. A library build script reads canonical metadata and generates typed identity constants, with Cargo invalidation for manifest/environment changes. Both frontends render that identity; xtask independently checks the packaged boundary against Cargo metadata. macOS uses product semver for CFBundleShortVersionString and the decimal build counter for CFBundleVersion.

## Workspace visualization and typography

Core `Target::timing_model` derives static origin-zero pulse occupancy and sinusoidal-envelope bounds from the synthesis primitives, with 250 ms–4 s spans and a fixed 32 × 512 column bound. Pure observers do not advance phase or touch control mailboxes. Both frontends consume shared summaries; GUI path generation supplies geometry only. Static pattern explanations live beside components in the scrolling document, separately from the bounded bottom output drawer and persistent transport. Large text/small space can use a focused monitor window with one independent scroll region and keyboard access to its controls and warning text; the drawer remains unscrolled. Full diagnostics use a separate selectable snapshot reader.

Library `WaveformCapture` owns samples' extrema, meters, source/session, rate, span, observation, counters and display scale as one immutable snapshot. Core extrema reduction examines every sample and rejects nonfinite values. Fit uses both ears' peak with a silence limit of one; levels use normalized RMS arithmetic to retain very small finite magnitudes. Holding retains this full capture across session replacement, while current progress/terminal state remain authoritative. Shared output-view state distinguishes Live/Held/Stale/Waiting/Unavailable/Last capture. Receipt time advances only on a changed source observation. Current coverage warnings recover independently of cumulative gap history. Incomplete coverage and fixed-range advice stay visible and accessibly readable without automatic speech; stale/unavailable monitoring and capture errors use polite announcements. Backend underrun counts have an independent polite label that survives coverage recovery. A reserved font-scaled warning row keeps automatic observation changes from changing the responsive pane choice. Accepted target projections are cached from the monitor poll, avoiding another control lock.

GUI typography resolves the native SystemUi face and platform size. Windows message metrics include the system text-size preference and are read at 96 DPI; the window applies display scaling once. Linux selects the active desktop namespace, parses native Pango or QFont descriptions, and listens for portal/GSettings/GTK changes on one worker. Bounded portal calls and one coalesced value keep preference I/O off the UI/audio paths. The adapter's tick drains that value even when idle. Native library code stays mapped for process lifetime because registered native types/event sources may outlive the listener. About uses the shared build identity and embeds the complete root license in a separate license window; only application/Help menus expose About. Component notices resolve relative to the executable, using `Contents/Resources` inside a macOS bundle, independently of the working directory. Window deactivation suspends incidental field commits; explicit actions still commit pending text before capturing a draft.

Native motion adapters coalesce enabled/disabled/unknown states off audio processing. AppKit accessibility, Win32 animation and GNOME GSettings/KDE portal queries supply effective preferences. Unknown uses diagnosed live drawing; explicit Hold/Return overrides survive later preference changes until Follow system; the workspace owns that policy.

The macOS text stack applies logical-size optical variants and tracking consistently across shaping, metrics and drawing; [the pinned toolkit patches](../third_party/README.md) retain device-scale-independent spacing.

On X11 desktops using GTK font settings, resolved GDK window scaling drives window DPI while text/font DPI drives font size. This keeps text enlargement out of minimum/preferred window geometry. The pinned Winit adapter retains Xft/RandR fallback and explicit scale overrides.

Pango absolute-pixel descriptions retain their units: window backing scale applies, while point-font DPI/text scaling does not multiply an absolute pixel size.

Viewport changes coalesce into a deferred UI refresh. Native auxiliary windows open or close after layout/drawing callbacks return, so creating another graphics context cannot interrupt the current frame. Shutdown stops that pending refresh before the workspace joins its workers.

## Foundation boundaries

Core remains `no_std` with `alloc`: physical vocabulary, the one Unreleased schema-3 document, validation and synthesis have no frontend or device dependency. `Recipe` owns portable UUID/history, authored primitive/pair nodes, description, bibliography, scoped evidence and flat lineage. Primitive `Stimulus`/`Target` remain DSP inputs; lowering preserves source order and assigns owner/lane identities. Process snapshots/editor IDs and local membership belong to the application. Editor baselines compare full persisted content; publication may add observed history without erasing later editable changes.

The application owns editing, publication, portable sessions and operation preparation. `workspace/operations.rs` prepares complete immutable Save, Export and audio candidates without committing, allocating snapshot IDs or issuing effects. Commands recheck admission, prepare, then commit once; path prompts retain captured content. Synchronous CLI workflows reuse loading, realization and publication directly. `workspace/tasks.rs` owns production launch/channel/join mechanics; the workspace owns continuation decisions. Results do not release slots before join, and launch failures are visible terminal outcomes.

Library projections cache contents/query/selection identities and inspection rate independently of editor revisions. Candidate parsing uses document-local committed/input revisions. Acoustic analyses use component identities, numeric bit patterns, routing/kinds, finite envelope and explicit rates; notes and source attribution do not trigger compilation; monitor capture keys retain session/publication/span/scale identity. GUI editing, actions and auxiliary callbacks are separate modules installed by the production adapter. Renderer tokens retire on removal/replacement and are never reused, including Undo. Exhaustion disables editor callbacks and asks the user to save and restart. Native window, font, keyboard and accessibility mechanics stay in the GUI.

Library search covers the current title, own notes and research, plus explicitly attributed retained source notes/research. Reimporting an origin replaces that immutable snapshot and invalidates search and views. `RecipeSnapshot` owns a two-rate success/error realization memo shared by snapshot clones; library labels, details, readiness and export all use it. A new identity receives a fresh memo. This application/preparation lock is never acquired by a sample callback, which renders its already captured `Signal` or live target.

`ActionView` supplies Library Listen/replacement wording and operation-specific availability. Save/Import workers may coexist with new audio; prompts, exports and queued actions retain their own admission rules. Slint renders supplied availability directly and uses application-owned sizing labels. File-busy status is descriptive, not a substitute for command admission.

File commands capture `FileKind`, then launch through `Workspace::spawn_file`; the production worker executes `FileKind::execute`. Audio has the parallel launch boundary. Unit tests and the nondefault `test-support` feature expose `workspace::testing` fixtures: real commands still admit, capture, launch, poll and join real workers, while test drivers order filesystem execution/result/exit/panic or inject launch failures. GUI dev tests enable that feature to exercise actual installed accessibility/button bindings without opening a device. It is a testing facility, not a production scheduler or capability override. Existing real-device and uninstrumented thread/filesystem integration tests remain separate assurance.

## Persistent library and external files

`library::{LibraryRoot,LibraryStore}` implement the single managed envelope format 1. `LibraryKey` grants Built-in/User/temporary capabilities independently of declared UUIDs or titles; curated UUIDs are reserved. A record carries a random revision, exact plain recipe text and local Added here/Trash history. Expected tokens combine revision with SHA-256 of exact outer bytes. Shared/exclusive nonblocking root locks coordinate readers/writers without age/PID lock stealing. Root-relative capability handles, nofollow descendants, bounded regular-file reads and exclusive private stages protect publication. Atomic replacement uses rename; create uses no-clobber hard-link publication. Exact receipts distinguish unchanged, published, published-with-warning and publication-unconfirmed; Recheck never blindly republishes. Arbitrary noncooperating edits cannot be excluded after a final check.

`collection::EntrySummary` is disposable, compact and free of acoustic target compilation. One `CatalogQuery` supplies correlated predicates, unique counts/groups, explicit half-open instant ranges and deterministic sorting to CLI and Slint. Scan limits bound directory work (including unknown/recovery artifacts), raw bytes and decoded recipe bytes, including invalid embedded documents. Incomplete inventories retain healthy results and diagnostics; the desktop preserves previously unseen rows as last observed. Root and record stages are reported without promotion or deletion. There is no authoritative index or migration journal.

`Workspace::configured_library` is the production desktop entry point. Invalid root configuration leaves Built-ins usable and refuses persistence instead of falling back to external saves. `Workspace::with_library` binds an explicit store for embedders/tests; `Workspace::new` is an in-memory workspace with the existing explicit file-panel save workflow. The persistent workspace retains summaries plus one full selected User record. Scan/load/save/recheck/init run on its serialized file worker; focus/manual refresh cannot race older tasks from the same workspace into the index. Draft, saved record, selected key, playing session and held capture stay separate. A managed finite Play revalidates its selected version on the worker before device preparation.

`external::{ObservedFile,ExternalWriter}` retain an opened-file identity and exact-byte hash. External Save keeps the portable identity/creation history, checks the observed version even for no-op, and publishes a synchronized verified sibling stage under a stable adjacent cooperative lock. A new edit records the observed modified time; no-op preserves original bytes. External applications need not honor that lock, so a race after the final check remains possible. Confirmed/uncertain receipts and Recheck are separate from ordinary failures. Managed add/edit/Trash/purge never invokes this external writer.

Native calendar fields normalize inclusive local dates through the next local midnight, including daylight-saving offset changes; ambiguous/nonexistent midnights are refused. The CLI takes explicit-offset `[from,before)` instants directly. Portable history is never inferred from filesystem dates or publication years. Recipe, managed-record and machine-output versions are independently 3, 1 and 1.

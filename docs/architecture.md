# Architecture

Auditory Lab has a pure synthesis core, one shared application library and two frontends. Cargo's direct dependencies express the direction: CLI and GUI depend on `auditorylab`, which depends on `auditorylab-core`. The library re-exports the model types needed by callers. Frontends select input, present results and own their threads; domain decisions belong in the library and core.

| Package | Responsibility |
|---|---|
| [`auditorylab-core`](../crates/core) | Recipe schema, model, validation, catalog, seekable and live synthesis, recipe writing and waveform extrema. |
| [`auditorylab`](../crates/lib) | Loading, contextual errors, notices, WAV export, editable drafts, control ranges, shared presentation, atomic publication and default-device playback. |
| [`auditorylab-cli`](../crates/cli) | clap grammar, terminal layout, exit codes and interrupts; binary `auditorylab`. |
| [`auditorylab-gui`](../crates/gui) | Slint controls, native dialogs, independent audio/file workers and scope paths. |
| [`xtask`](../xtask) | Archives, notices, smoke checks and release notes. |

## Recipe to signal

The core is `no_std` with `alloc`. `Preset` contains a `Stimulus` and optional `About` text. A component contains ear routing, peak level, a tone or click carrier and optional sinusoidal or rectangular modulation. A private serde representation keeps the strict schema independent of the public model.

Parsing checks byte length, UTF-8, schema version and TOML structure. Numeric values are validated by `Stimulus::signal(rate)`: duration, fade, fade overlap, component count, each component and finally each ear's peak sum. The resulting immutable `Signal` stores resolved frame counts and validated voices. Its clone can be shared across threads.

Tones and sinusoidal modulation have a 64-bit integer phase step, rounded upward from the exact binary64 frequency ratio. Frame n uses wrapping multiplication by n. Tones convert the phase's signed top 53 bits to cycles before evaluating portable `libm` sine. Pulse width is rounded to whole frames. Exact rational period counts place each onset on the first frame at or after it; comparing counts at n and n−W gives a constant open width. The exact closed-frame rule keeps successive pulses separate. Voices are summed in recipe order, then the raised-cosine fade applies. The [preset guide](presets.md#waveforms) defines the formulas.

`Signal::frame(n)` evaluates any frame directly. `render(start, out)` fills an arbitrary block, returns its active length and zeros the tail. It allocates nothing, locks nothing and performs no I/O. Each output owns its cursor. Integer phase, binary64 arithmetic and portable `libm` preserve sample bits across platforms and build profiles; pinned digests test that contract.

Catalog source files are embedded by the core build script in natural ID order. The public catalog table is generated from the directory. `waveform::trace` renders every frame of a clipped window into fixed stack scratch and reduces equal partitions to per-ear minima/maxima. Its caller reuses the output vector. Single-frame pulses reach their bins' extrema.

## Live synthesis

`live::Target` holds up to 16 validated components and caller-chosen stable identities at one rate. `Component::validate` supplies individual row errors; target validation also checks the total peak sum. `Engine` uses 32 fixed slots so all 16 old generators can crossfade with their replacements. It allocates nothing while setting targets, rendering or stopping.

Tone and sinusoidal-modulation oscillators advance integer phase accumulators. Constant settings match the seekable signal after the start ramp. A 30 ms transition interpolates per-ear levels, phase steps and depth. Matching component identities and generator kinds retain phase; pulse or kind changes crossfade generators. Each transition connects validated endpoints with shared progress, bounding the per-ear sum. Changes during a transition coalesce to the newest waiting target. Stop queues silence after the current transition; its fade takes 30 ms and the request can span almost two ramps. The engine ends at `Signal::MAX_FRAMES`.

## Library boundaries

A loaded library `Preset` holds an origin and an `Arc` to the core recipe. `Preset::at(rate)` returns a `Sound` with an `Arc<Signal>`. Files are opened nonblocking on Unix, and admission checks the opened handle before bounded reading. Explicit readers retain stream semantics. Errors carry a category, contextual message, original cause and an optional leftover path; frontends branch on the category.

WAV encoding renders blocks and rounds to stereo binary32 samples. Header size arithmetic chooses RIFF or RF64. Export updates shared progress after each written block. Publication stages output in the destination directory, syncs it, checks cancellation and persists it with or without replacement. Failure cleanup owns only that partial file and names it if removal fails. CLI publication always refuses replacement; GUI replacement follows native Save confirmation.

Playback preparation binds the default device snapshot to values validated at that device's rate. The callback owns a `Source`: a finite `Arc<Signal>` with a cursor and optional stop fade, or a boxed `LiveGenerator` with a validated target mailbox. The box is allocated before stream creation. Both sources render into preallocated scratch, report completion by returning fewer frames than requested, and preserve the backend-timestamp drain logic. Output conversion uses channels 0/1 for left/right and silences additional channels.

`LiveGenerator::new` validates and stores its initial whole target before rendering. `prepare_live` uses that same generator at the bound device rate. The generator also supports device-free public-library consumers. `LiveControl::update` validates a draft at the device rate before replacing the waiting target. The callback uses `try_lock` once per device buffer, skips busy or poisoned locks, and copies the newest target/revision into the engine. It never blocks or frees memory. Whole-target replacement preserves the previous valid sound when an edit is invalid. Accepted revisions increase only when canonical audio targets change; metadata and identical refreshes do not restart ramps. Active and settled revisions follow actual generation.

Supervision turns cancellation into an atomic stop request. A finite source fades with gain `1 − (t+1)/R`, with R capped at its remaining frames, and reports Cancelled after draining; the CLI retains exit130. A stopped live source reports Played. If completion does not follow Stop within two seconds, supervision forces silence and returns Cancelled. Both sources retain the 30-second stall watchdog; live playback has no overall deadline apart from the core's frame limit. Terminal atomics use first publication wins, and backend diagnostics stay outside sample processing.

`Draft` owns editable metadata and components with identities that are never reused within that draft. Slider ranges and default components live in the library. Saving serializes finite values through the core's schema-2 writer, checks the reader's byte limit, then uses staged publication. Shared title, research, duration and dBFS helpers keep frontend presentation consistent.

Progress stores the callback's starting source frame minus the reported output latency, floored at zero. Export uses the same progress type for written frames. Listening notices and version wording live in the library.

## Frontend threads and packaging

The CLI uses clap for source exclusivity and command grammar, textwrap for prose, and a byte-preserving catalog recipe writer. Interrupt handling begins after input loading. One mapping from library error category selects the exit code.

The GUI's plain `App` state is separate from Slint wiring. One audio worker owns finite/live playback and one bounded file worker owns import, recipe saving or export. Save commits/clones a draft before opening the native panel and continues independently of audio. Draft-owner identity rejects obsolete results; content comparison preserves later edits as dirty. Export requires idle audio to avoid competing render loads. Prepared monitor readers capture session identity and device binding; navigation and selection do not rebind them. Pending text/focus stay in frontend state, while validation and generated quantities come from the library. A saved-content snapshot protects dirty drafts; a save result records exactly the snapshot written, preserving later edits. Native Quit, File Quit and close share both workers’ drain/join and Save/Discard/Cancel policy. macOS native file panels install an audio-only Stop accessory before presentation; its action directly requests the audio cancellation flag. Windows/Linux use a separate modeless audio-controls window during native selection. File cancellation and audio Stop never share a cancellation flag. Queued playback replacement depends only on audio cleanup; document replacement depends on file completion, and closing depends on both. Readiness and failure handling use that same dependency policy, so an independent file failure remains visible without cancelling queued playback, while a failed required Save cannot authorize a destructive action. A small macOS bridge implements Cocoa's optional asynchronous termination method on the known winit delegate, leaving its object layout, other callbacks and menu/context-menu routing intact. Cocoa receives its final answer only after the shared close policy resolves; an unexpected delegate or existing handler fails clearly at startup.

`cargo xtask dist` builds one supported target, generates product-specific notices and archives, then extracts and inspects the delivered binaries. macOS executables must have exactly one expected architecture; app marketing version/build counter, signature, permissions and executable identity are checked. Apple silicon and Intel have separate native CI jobs and uploads. `collect-assets` derives the complete archive set from the same target/product mapping and rejects missing, duplicate, stale or unexpected files before checksums/attestation. The reusable [CI workflow](../.github/workflows/ci.yml) supplies release builds; [contributing](../CONTRIBUTING.md#packaging-and-releases) describes publication.

## Generated observations

Core component facts distinguish requested rates and actual integer-phase rates. Rational pulse repetition and rounded width frames retain their rendering semantics. `Engine::observation` is side-effect-free fixed storage for the last generated frame (or None before generation), with up to 32 outgoing/incoming/continuing slots and active/settled target revisions. Core code has no device clocks, locks, frontend strings or monitoring I/O. Observation does not change sample formulas or determinism.

The library binds a process-local session ID, source snapshot and device configuration before playback. Optional monitoring has quantities-only or waveform detail. A callback attempts one nonblocking mutex acquisition per device buffer. It appends actual mixed/faded/clamped stereo f64 scratch samples before output conversion and publishes coherent generated-frame state. It neither copies old history nor formats/reduces/allocates under the callback. A skipped write creates a source-span discontinuity; the next write resets contiguous history. Poisoning disables observation with an off-callback diagnostic, independently of audio terminal authority.

Waveform storage is at most ceil(sample-rate/10) stereo frames: 76,800 frames (1,228,800 sample bytes) at 768 kHz. All transport and consumer storage is allocated during preparation, including initialization of lazily allocated mutex storage. Readers use try_lock to copy only the requested bounded window into preallocated storage, then release it before calculating extrema, peak/RMS, descriptions or paths. Quantities-only mode allocates no sample history. Monitoring misses and backend underruns are distinct counters.

The shared `SoundSummary` interprets independent click/gate/AM processes, inactive modulation, steady carriers and narrow equal-gain same-route monaural pairs. It recognizes interaural difference only for exactly one active unmodulated left-only tone and one right-only tone. It reports individual generator quantities/roles for other mixtures and crossfades. Status identifies the last generated frame; window spans identify the displayed samples. Neither is microphone input, SPL, a perceived-beat measurement or a latency-aligned acoustic playhead. The existing backend estimate remains the authority for estimated output elapsed time, and existing terminal/drain logic decides completion even if monitoring misses its final publication.

## Build identity

`workspace.package.version`, the positive `workspace.metadata.auditorylab.build-number` and an optional validated source revision are separate facts. A library build script reads canonical metadata and generates typed identity constants, with Cargo invalidation for manifest/environment changes. Both frontends render that identity; xtask independently checks the packaged boundary against Cargo metadata. macOS uses product semver for CFBundleShortVersionString and the decimal build counter for CFBundleVersion.

## Workspace visualization and typography

Core `Target::timing_model` derives static origin-zero pulse occupancy and sinusoidal-envelope bounds from the synthesis primitives, with 250 ms–4 s spans and a fixed 32 × 512 column bound. Pure observers do not advance phase or touch control mailboxes. Both frontends consume shared summaries; GUI path generation supplies geometry only. Static pattern explanations live beside layers in the scrolling document, separately from the bounded bottom output drawer and persistent transport. Large text/small space can use a focused monitor window; full diagnostics use a separate selectable snapshot reader.

Library `WaveformCapture` owns samples' extrema, meters, source/session, rate, span, observation, counters and display scale as one immutable snapshot. Core extrema reduction examines every sample and rejects nonfinite values. Fit uses both ears' peak with a silence limit of one; levels use normalized RMS arithmetic to retain very small finite magnitudes. Holding retains this full capture across session replacement, while current progress/terminal state remain authoritative. Shared output-view state distinguishes Live/Held/Stale/Waiting/Unavailable/Last capture. Receipt time advances only on a changed source observation. Current coverage warnings recover independently of cumulative gap history; audio underruns remain distinct. Accepted target projections are cached from the existing monitor poll, avoiding another control lock.

GUI typography resolves the native SystemUi face and platform size. Windows message metrics use logical 96-dpi units and WinRT text scale. Linux selects the active desktop namespace, parses native Pango or QFont descriptions, and listens for portal/GSettings/GTK changes on one worker. Bounded portal calls and one coalesced value keep preference I/O off the UI/audio paths. A 200 ms UI timer drains that value even when idle and retargets asynchronously rebuilt macOS application About items. Native menus can be absent or empty during launch/recovery and rebuilds; nullable first-item snapshots defer retargeting until the menu exists. Native library code stays mapped for process lifetime because registered native types/event sources may outlive the listener. About uses one identity/license builder; only application/Help menus expose it. Window deactivation suspends incidental field commits; explicit actions still commit pending text before capturing a draft.

Native motion adapters coalesce enabled/disabled/unknown states off audio processing. AppKit accessibility, Win32 animation and GNOME GSettings/KDE portal queries supply effective preferences. Unknown uses diagnosed live drawing; explicit Hold/Return overrides survive later preference changes until Follow system. Pending action admission and typed setting diagnostics are shared with whole-candidate commit/validation; GUI fields never reuse an unrelated row error.

The macOS text stack applies logical-size optical variants and tracking consistently across shaping, metrics and drawing; [the pinned toolkit patches](../third_party/README.md) retain device-scale-independent spacing.

On X11 desktops using GTK font settings, resolved GDK window scaling drives window DPI while text/font DPI drives font size. This keeps text enlargement out of minimum/preferred window geometry. The pinned Winit adapter retains Xft/RandR fallback and explicit scale overrides.

Pango absolute-pixel descriptions retain their units: window backing scale applies, while point-font DPI/text scaling does not multiply an absolute pixel size.

Viewport changes coalesce into a deferred UI refresh. Native auxiliary windows open or close after layout/drawing callbacks return, so creating another graphics context cannot interrupt the current frame. Shutdown stops that pending refresh before draining workers.

# Native graphical qualification

These scripts drive the production debug GUI through OS accessibility providers and native keyboard input. They do not call application callbacks or open audio. Each process uses an isolated library and `AUDITORYLAB_NATIVE_QA_DIRECTORY`; that private debug-only seam isolates onboarding configuration and is absent from distributed builds. Initialize the isolated library with the ordinary CLI before launching the harness.

Linux requires a private D-Bus session, AT-SPI registry, GTK desktop portal, X11 display, `xdotool`, Openbox, `sway`, `wayland-info` and system Python with `pyatspi` and Pillow. The Wayland case additionally starts a real nested Sway compositor with Pixman composition and verified xdg-foreign v2 export/import protocols, forces the application onto its Wayland socket and checks actual Wayland surface protocol. The outer X11 display supplies compositor input and output; it is not the Wayland implementation. Run separate cases:

```sh
scratch="$PWD/target/native-x11"
mkdir -p "$scratch"
target/debug/auditorylab --library-dir "$scratch/library" library init
timeout 240s dbus-run-session -- xvfb-run --auto-servernum --server-args='-screen 0 1920x1200x24 +extension GLX' bash crates/gui/native/linux-session.sh x11 "$PWD/target/debug/auditorylab-gui" "$PWD/crates/core/tests/fixtures/recipes/custom-derived-pair.toml" "$scratch"
```

Use `wayland` and a distinct scratch directory for the second case. The harness verifies provider operation names, first-frame geometry/pixels, multiline native input/modifier selection, repeated native chooser cancellation/reopening, actual file opening with the selected `My 3 Hz pair` fixture title observed through the provider, and nonempty protocol-specific portal parent handles. The Wayland case opens a native dialog before and after a debug-only one-shot hide/show of the production main window. It checks rendered-frame traces, old Wayland surface destruction followed by a new toplevel, fresh provider operation names and a fresh exported portal parent. The seam runs once after an observed native GL frame and a private parent-confirmation marker written by the OS harness after its first real chooser is cancelled. The debug-only gate expires after thirty seconds and supports only this fixed hide/show witness.

Windows requires an interactive desktop, UI Automation and native keyboard access. In PowerShell, invoke `windows.ps1` with `-Binary`, `-Fixture` and `-Scratch` absolute paths. It additionally checks the actual Win32 owner of each common file dialog. Missing sessions/providers/controls fail; there is no offscreen fallback or skip. Successful JSON output reports only the cases actually exercised.

Native waits have deadlines and CI must also bound the outer process to five minutes. Failures retain bounded provider-tree text and first-frame image evidence under the supplied scratch directory; portal/protocol logs stay there for diagnosis. Remove passing scratch after retaining the requested evidence ledger.

These scripts are prepared qualification inputs. Syntax checks do not qualify their native behavior. CI must execute them on the delivered source. macOS AppKit repeated Quit Save/Discard/Cancel requires its own observed cases in the final acceptance ledger.

The compositor choice follows observed protocol requirements: Weston 13 rendered native GL successfully but advertised no `zxdg_exporter_v2`, so RFD could not supply a usable portal parent. Sway 1.9 explicitly constructs both foreign-protocol versions in its [server owner](https://github.com/swaywm/sway/blob/1.9/sway/server.c). The harness requires the actual installed compositor to advertise export/import v2 before starting the application; it never accepts an empty parent.

The hosted X11 server exposes no DRI3/DRM render file descriptor, so wlroots cannot create its GLES compositor renderer. Pixman therefore composes the actual Wayland desktop. This does not change AuditoryLab's renderer: its production Winit/FemtoVG path must produce actual NativeOpenGL frames both before and after surface recreation. The rendered-frame notifier, native surface protocol, provider controls and nonempty foreign parents remain required. No compositor GL claim is made.

Windows hosted runners exposed a real interactive desktop and native error provider but only a system WGL implementation below OpenGL 2.0. Before the Windows graphical job, run `prepare-windows-mesa.ps1`. Its [private package manifest](windows-mesa.json) pins official MSYS2 Mesa 26.2.6 and the inspected transitive PE import closure by exact package version, HTTPS source and SHA-256. The helper checks every archive before extraction, refuses existing destination DLLs, and records delivered DLL hashes and package provenance. Its archives/extractions stay in `target/native-driver-runtime`; only small metadata goes in `target/native-windows` failure evidence. Fifteen required runtime DLLs go only beside the debug executable. Separate distribution jobs/profile outputs receive none of them.

The helper uses the hosted image's 7-Zip to unpack pinned packages. Mesa is MIT-licensed; individual dependency license expressions and official source-index links are retained in the manifest and complete package license files remain in the extraction. Mesa's [vendor guidance](https://docs.mesa3d.org/precompiled.html) delegates precompiled binaries to distributions; [MSYS2's package owner](https://packages.msys2.org/packages/mingw-w64-x86_64-mesa) supplies the version, digest and build-source record. The native process uses llvmpipe with two worker threads and verifies that its loaded WGL module is the authenticated debug-directory driver. The application still follows its ordinary production Winit/FemtoVG startup and existing OpenGL 2.0 refusal. No toolkit bypass, alternate Slint renderer, system driver installation or product redistribution is used.

The GTK chooser location shortcut is exercised with focus in its actual Files table, not the sibling Cancel action area. GTK3 exposes the location entry as editable AT-SPI `TEXT`; the harness requires that actual role, editability and keyboard focus before verifying the exact absolute fixture path. Local native controls established both facts independently before changing these predicates.

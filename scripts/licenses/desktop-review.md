# Desktop dependency and resource review

This document describes the selected integration and the source material retained by the notice generator. Published source identities and pinned upstream commits identify the reviewed producers; hashes establish identity, not legal assurance or native execution.

Slint runtime and compiler are exactly 1.18.1. The selected integration route is [Royalty-free Desktop, Mobile, and Web Applications License 2.0](https://github.com/slint-ui/slint/blob/v1.18.1/LICENSES/LicenseRef-Slint-Royalty-free-2.0.md), with the standard AboutSlint widget in Help -> About. Its grant is for integrated desktop/mobile/web applications. Its limitations exclude standalone Slint distribution, embedded use and exposing Slint APIs. Auditory Lab's source remains MPL-2.0. The full terms are retained verbatim. The [tagged FAQ](https://github.com/slint-ui/slint/blob/v1.18.1/FAQ.md#royalty-free-license) corroborates this choice. Attribution must also be checked in the actual GUI, independently of notice freshness.

`slint-framework.json` binds the published compiler commit and every standard widget/resource/license file, including generated assets from this otherwise host-side producer. `slint-REUSE.toml` is the upstream tagged source attribution map. Standard widget source carries the same Slint license alternatives. The map assigns Material icons in material/cupertino/qt to Apache-2.0, Fluent icons to Microsoft's MIT grant, Cosmic icons to System76 CC-BY-SA-4.0, and the SixtyFPS logo to CC-BY-ND-4.0. The relevant full license texts and copyright/source attribution are retained, including the CC-BY-SA text omitted from the compiler crate's LICENSES directory. AboutSlint uses the unmodified upstream logo. All framework assets are reviewed as a conservative source set; this does not claim every style is embedded into every product. There are no project-supplied images/fonts. System fonts are resolved at runtime.

[supplements.json](supplements.json) retains published version/repository/VCS identity and exact upstream materials. AccessKit retains its MIT/Apache grants, Lyon its Nicolas Silva grants, clipboard-win its Boost Software License, Taffy its MIT grant including the Stretch/Visly attribution, rspolib its MIT grant, and objc2 0.5.3 the upstream Steven Sheldon MIT text. The objc2 framework-binding notes are accompanied by the full MIT template, preserving upstream's Apple SDK derivation note. Multiple published versions have distinct identity entries; identical legal bytes are shared. `dispatch` 0.2.0 publishes an MIT declaration and author in its manifest but no separate license file at that commit. Its supplement retains that fact, exact manifest identity and standard MIT text without inventing a copyright year.

Normal dependency notices use each checked Cargo product ID independently with Cargo's actual target normal-edge traversal, then union the results. Cargo metadata alone includes inactive alternatives and does not establish the selected product closure. Metadata remains the identity authority; unknown or ambiguous tree identities reject. Normal proc-macro source notices are retained without claiming host proc-macro code is shipped. Build-only tools are not generally reclassified as runtime; generated widget material is accounted for explicitly.

Both products share one macOS 15.0 supported/package deployment minimum for Apple silicon and Intel. Isolated builds and reviewed exact native import policies remain separate by product. The common macOS declaration is checked on each final executable and the GUI bundle. Linux X11/Wayland/font/D-Bus/portal and Windows GNU LLVM runtime/import behavior require actual per-target qualification. A package gate rejects unknown native inputs/imports rather than assuming they are licensed or safe because of a suffix or location. Native execution, accessibility, picker behavior and minimum-OS execution cannot be inferred from these source materials.

The GUI uses `windows-targets` 0.52.6 system import libraries through Winit's windows-sys route. `windows-import-libraries.json` records both GNU LLVM architecture producers, VCS identity, full archive hash and exact selected-member vocabulary. The reviewed archives contain 371 system-library member names for each architecture: short COFF imports and ordinary COFF import-descriptor/null-thunk records only, with sections `.idata$2` through `.idata$6`; no implementation/text section. The crates' MIT/Apache notices are in the normal closure. Runtime verification binds exact registry producer paths and hashes before allowing these GUI-only libraries; it never accepts arbitrary `.a` files. Separate GUI OS imports cover GDI software surfaces, DirectWrite fonts, Winit IME/DWM/controls and AccessKit UIAutomation/MSAA. Actual Windows link/import/extracted execution evidence is required on both architectures.

Windows document admission in the shared app uses the already locked `winapi-util` 0.1.11 producer (upstream commit `803874c57dc1f10ecd42f7c86d9de72f53818432`). Its safe `file::typ(&File)` wrapper borrows the opened handle and calls `GetFileType`; the app rejects non-disk types before metadata or reading, then checks opened-file metadata for regular-file admission. The binding imports `GetFileType` from Kernel32, already in both product import policies; no import allowance or handwritten unsafe/FFI exception was added. The dependency edge is confined to the app's normal `cfg(windows)` dependencies, so both frontends share this admission rule. Cargo's actual per-product target queries now include it as Windows runtime material; its prior appearance in the complete Rust standard-library copyright bundle was not evidence of inclusion in either product's own normal closure. Published `COPYING`, `LICENSE-MIT` (Andrew Gallant, 2017) and `UNLICENSE` are retained under the declared Unlicense OR MIT choice. Actual owned-pipe/device rejection and native link evidence remain required on both Windows architectures; source review alone does not establish native liveness or deadlines for arbitrary OS/filesystem calls.

The selected drawing profile includes FemtoVG/WGPU alongside software. Runtime/compiler are exactly 1.18.1. The checked feature graph permits the framework's matching internal WGPU 30 integration only, excludes Skia, static DXC and public raw-GPU APIs, and preserves CPU audio generation. Locked producers retain their published grants, including profiling MIT/Apache, SPIR-V Apache and its generated Khronos grammar's pinned upstream license, and Metal framework bindings' Apple SDK derivation note plus MIT grant. SPIR-V grammar provenance follows rspirv commit `8afc3d0ac8e158128cd1410bb2e4b4c26ab11bb4` to SPIRV-Headers commit `04f10f650d514df88b76d25e83db360142c7b174`; generated Rust source bytes and full upstream grant are retained. No driver or DXC implementation is bundled. Metal is included in the macOS GUI import envelope; Direct3D/DXGI/OS FXC are included in Windows GUI system imports. Driver and dynamic-compiler availability require native evidence.

`rtrb` 0.4.0 is a reviewed MIT/Apache dependency without runtime dependencies. It provides the bounded SPSC transfer used for optional signal observation, with native atomic support and fixed heap-free packets. Construction is outside the callback; reviewed push/pop paths use bounded atomic operations without allocation, waiting or locks. The application bounds queue/ring/copy/geometry memory independently. This is generated-sample observation, not microphone capture or a promise about DAC playback.

The modified `i-slint-backend-winit` 1.18.1 retains the selected Slint grant and every upstream legal file. `patched-dependencies.json` and the [vendored provenance record](../../vendor/slint-winit/AUDITORYLAB.md) identify the exact registry crate, upstream VCS commit and two-file patch. The gate reconstructs the original modified files and rejects changed or missing source/legal bytes. Ordinary macOS Quit routes managed windows through the application close/cancel/join flow. This does not promise cancellation of forced termination or logout. Packaged notices identify the modified source and exact upstream/patch digests; source access is through the archive's immutable qualified source link, or explicitly unqualified local builder checkout.

Native qualification checks FemtoVG/WGPU and forced-software first frames separately using the generated production MainWindow fixture. A WGPU renderer string alone does not identify a physical GPU adapter; report that property as unverified unless independently established. Interactive resource/accessibility observations require separate evidence against the packaged executable. Neither upstream source inspection nor first-frame instrumentation establishes those properties.

Wayland title rendering uses Winit's supported crossfont CSD route, preserving title text and controls. The [SCTK 0.10.1 patch](../../vendor/sctk-adwaita/AUDITORYLAB.md) changes only its optional crossfont requirement from 0.8 to 0.9 to match Fontconfig's links producer. All original source/features/legal files and the inactive Cantarell font remain; its embedded copyright and full SIL OFL terms are retained separately. Crossfont's reviewed FreeType calls are available in the supported distribution ABI. Both Linux Cargo target overrides skip freetype-sys build.rs entirely and link system FreeType. The bundled FreeType 2.13.2 C corpus is neither compiled nor shipped; its wrapper MIT entry cannot be mistaken for its native license. Security-updated distribution FreeType/Fontconfig packages are required. Exact ELF imports and native package-version evidence are mandatory on Linux. Label virtualized Linux execution and virtual X11/Wayland display evidence explicitly; those results cannot qualify physical GPU, input-device or assistive-technology behavior.

The typed-index-collections 3.2.3 lock selection is within the compiler's declared compatible range. Later compatible versions declare optional bincode that is unused by this compiler yet retained in the whole lockfile; the 3.2.3 producer avoids that unmaintained material without stripping features. This does not promise a separately maintained 3.2 branch. Reassess source/API correctness, advisories and selected features when updating that producer or the compiler.

The exact Slint profile includes its pinned unstable-winit-030 bridge for borrowed focus queries and a propagating occlusion observer. The application has no direct Winit dependency, retained native window ownership or raw graphics API. The selected Slint grant and backend provenance apply to this bridge too. Native hidden/unfocused monitoring behavior requires actual packaged UI evidence.

System-only linkage does not remove the engine's own license obligations. The FreeType License expressly defines use to include linking a program and requires the FreeType Team acknowledgment for binary redistribution. The exact acknowledgment and complete reference distribution copyright/grant bundles for libfreetype6 2.11.1+dfsg-1ubuntu0.4 and libfontconfig1 2.13.1-4.2ubuntu5 are retained as Ubuntu 22.04 ARM64 reference materials; system-library-notices.json binds their producer identities and bytes. They are labeled external OS libraries, not MIT bindings or bundled implementations; full distribution inventories can cover additional source/build/package material. Current runtime package versions are separate native evidence, and security updates remain required. The selected FreeType engine route uses FTL; the application remains MPL-2.0.
